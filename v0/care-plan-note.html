Documentation rules
  • One authenticated signature covers every order enumerated in it. CLIA requires a valid request from an authorized person, not a per-test signature. State law or the performing lab may require more.
  • Signing orders and locking the note are separate acts. Sign & send transmits the orders; an order can transmit before the note is locked. Locking freezes the note, generates the Note PDF, and creates the legal-record DocumentReference in Canvas.
  • Cash-pay: an indication is captured, not a payer diagnosis code. A valid attributable request, not a billing dx, is what the order requires.

Baseline findings

finding Nine mentions of a reimbursement model that does not exist: cash-pay wellness, no billing dx captured, no payer diagnosis code, and a documentation rule headed Cash-pay. Aleron is a membership programme with no physician billing, so the copy is explaining an absence nobody asked about and implying a payer relationship that is not there. The indication itself is worth keeping, but for defensibility rather than for a payer. Recorded rather than fixed, per v0's rule; v2 and v3 carry the correction.

finding The shipped copy is right about the note and silent about the order. Generates the Note PDF and the legal-record DocumentReference in Canvas matches the API exactly, including the PDF attachment. But Sign and send transmits the orders never says what the order becomes in Canvas, and it cannot become anything through the API: ServiceRequest is read and search only. Recorded rather than fixed, per v0's rule.

finding The attestation is a 22px unstyled square with no ring, no focus treatment and no error state, and it gates a CLIA order transmission. The design system permits a checkbox for a physician attestation, but not one that is quieter than every field above it.

finding The two legal acts are stacked in the same scroll with the same button vocabulary. Sign & send 4 orders is primary, Lock note is secondary, and only a 13px hint line under each says which one is irreversible and which one transmits.

finding The sheet carries its own shadow (--shadow-sheet, a two-layer 48px drop) on a page that already has a Tier-1 card in its tab strip. This is the second elevation on the surface and the only place in the product where a shadow is declared by hand.

finding Row 04 in the manifest reads … with fasting insulin at…. The payload builder truncates any derived title over 90 characters, and the truncation lands mid phrase in a legal document’s scope list while the untruncated text is visible two inches below in the same note.

finding Every field label on this screen is the audit face in tracked caps: the meta grid keys, the section eyebrows, the collection-method label, the order statuses and the autosave hint. Only the body text and the textareas are in the voice face.

finding Autosave state is announced as DRAFT AUTOSAVED · NOT A LEGAL RECORD in tertiary caption at the top of the sheet and never repeats. On a note this tall the physician signs orders 1200px away from the only statement of the document’s status.

note The order ledger renders twice: once per problem card and once consolidated. The per-card copy has an empty source column and identical remove controls, so removing an order in one place silently changes the other list.

note Genetics can never transmit from here. A queued genetics kit shows the status Via lab orders and stays in the note as documentation, because the counseling gate lives only on the Lab Orders route. Nothing links the two.

note Every problem card is editable free text pre-filled from the engine, and edits are counted but not diffed. The note can diverge arbitrarily from the run it cites, and the provenance band at the top still names run #7c1a9f04 as the source.
