Opt-in care plan

One screen, not a fourth complete version. v3 exists to put a single question in front of the room: should a care plan open empty and be filled by the physician, or open drafted and be pruned by them?

The question

v2 follows the canonical build: the engine drafts every candidate straight into the note and the physician removes what does not belong. v3 follows the shipped portal instead: the note opens empty, the engine ranking is a list of candidates, and nothing enters the record until someone puts it there. The difference matters because the note becomes a signed legal record. Under v2, an engine draft is the default content of that record unless a physician actively intervenes; under v3 it cannot be, but the physician does more work on every patient and a genuinely correct suggestion can be missed by omission rather than rejected on purpose.

Both are defensible and the sources disagree. The shipped portal at Aleron-Web is opt in. The reference surface and apps/physician/src/carePlanView.js are both opt out, with per-item controls inline on every problem and order. What is not defensible is what v2 had until this screen was built: opt out with the controls moved into a side pane, which is the draft becoming the default with the objection made expensive.

What v3 changes, and what it keeps
  • Changed. The note opens empty. Six suggestions sit in one list in engine order, each a real checkbox with its rationale and the orders it would queue. Three are checked in this fixture. There is no rank badge and no QALY figure on a row: Aleron-Web prints those, the canonical build does not, and ranking belongs on the action map and in the reasoning trace.
  • Changed. One list, not a candidate panel above a note. The chevron opens a row to edit its assessment, plan, disposition and orders, so an item is read and edited in the same place.
  • Changed. A running tally is pinned to the foot of the document: 5 orders staged, 4 authorizable · 2 required, each needing a disposition. One line at every width. v0 has the same dock and it is the thing that makes an opt-in model safe to work in.
  • Changed. Declining is recorded rather than silent. An excluded row carries an editable Reason not carried, so the note documents what was considered and set aside, not only what was kept.
  • Kept. The required channel still cannot be dropped in silence. The ATM obligation carries a disposition it must be given — included, deferred with a reason, or excepted with a reason — because a genetics obligation is not ranked against opportunities and is not the physician's to omit by inaction. It can be set aside; it cannot be ignored.
  • Changed. Four steps instead of one scroll. Plan, note lock, order authorization and patient release are panes behind a rail, so the plan step, the one worked every visit, is about 2,800px rather than the 9,800px the whole page ran to. This is v0's two-step wizard idea extended to four, but it stays one file and one URL: every act still completes in its own card and nothing navigates away.
  • Changed. Order authorization no longer waits on the note lock. The card listed the Preview note is not locked, act 1 comes first as a blocker, which contradicted this screen's own account of why there are three acts. An order can transmit while the note is an open draft, and v0 already said so. The rail is a tablist rather than a wizard for the same reason: two of the four steps have no order between them.
  • Kept. Everything below the document: the workbench rail, the three commit acts and the release surface with its attestations. They are the same acts with the same attestations as v2, now separated into steps and no longer chained to each other. The only difference in the document itself is how content gets into the note.
