How the panel differs from the inbox, and what the risk read is worth

The inbox is filtered to states whose Physician visible column in the Role and Release Matrix, section 4, permits an act. The panel drops that filter, which is why released and tracking patients appear here and not there. Neither list ranks patients by the action layer's own output: the lifecycle is the sort key, because a packet that is ready outranks one that is merely alarming.

The domain read is a summary of five modelled domains plus a systemic roll-up. Only cardiovascular carries a validated model today; the rest are shown with their tier and carry model provenance pending inside the chart, where the claim can be qualified properly rather than compressed into one word on a list row.

A tier is worked out when you ask for it and is not kept. That is why the read is a button on the row rather than a column that is simply there: a tier is a reading of everything known about a patient at the moment it was taken, and a kept one would go on looking correct for as long as it took the next result to arrive. The list would then be showing you nine tiers, none of which described anyone.

What changed, and where it came from

fixed The density default demanded nine engine runs before anyone asked a question. With risk by domain shipped aria-checked="true", so first paint wanted a six-domain read for nine patients and Load next 25 wanted a hundred and fifty more. Nothing can serve that. No Canvas resource holds an Aleron risk tier: Observation has no update and its create is restricted in practice to vitals and panel-shaped categories, and the live instance refused a cardiovascular ten-year score outright with 422 Requested Sign does not exist; CarePlan and Goal are read and search only; DetectedIssue is a decision-support flag, not a graded score, and its search is patient-scoped; UPSERT_PATIENT_METADATA stores a value per patient but cannot list one, so it can hold a tier and can never answer "give me the tiers for these nine". So each tier means running the engine over that patient's whole packet.
The remaining way to make the column cheap is to keep the tiers somewhere in Aleron keyed by patient id, and that is exactly the residency line strict data residency refused, so it is refused rather than priced. It is also wrong on its own terms: a tier is a reading of everything known at the moment it was taken, so a kept one goes stale silently the second a lab lands and the physician scans nine tiers that no longer describe anybody.
Default is Lifecycle only. The control itself is unchanged, which is the point: the screen already argued in prose that the risk read is a second question, and the default was contradicting its own copy.

new Inside the domain density the read is per row, on request. Flipping the density on does not fetch nine reads either, it reveals nine buttons. Each is an ordinary disclosure: aria-expanded on the button, the tiers as its aria-controls target, so no live region is claimed and none is needed. Ethan Park ships already read, because a row that has been asked and a row that has not are both real states and the screen should show both rather than describing one.
The cost is real and is the correct trade: the panel's most distinctive column is one click away instead of visible. What it buys is that a tier on this screen is always a tier somebody asked for, computed from the packet as it stood at that moment, which is the only condition under which the number means anything.
Marcus Bell keeps a button like everyone else and it reveals six insufficient data. That is deliberate. You do not know a packet is too thin to model until something has looked at it, and hiding his button would be the screen knowing a thing it has not yet been told.

fixed One string per lifecycle state, and the panel's wording is the one that won. Inbox ranked Review pending and Ready for signature where this screen ranked Physician review pending and Plan ready for signature, and both claimed to be literals from section 4 of one matrix. The reason this screen's wording is the survivor is not that it is longer: these strings become Task.input labels, which Canvas treats as free text, creates on demand from whatever it is sent, and hands back through label=. The label is the query key. It shares a namespace with anything the clinic's own staff type into Canvas, and Review pending is a phrase anyone might type. Physician review pending is not.
Nothing in this file changed as a result, which is the whole finding: this screen was already right and was being contradicted from the other one. Both rank tables now carry the same nine strings.

finding The queue primitive is Canvas Task, and three of these nine rows do not fit it. The row set and the count come from two genuine cross-patient calls, GET /Patient?_has:CareTeam:participant:member=Practitioner/{id} for the panel and GET /Task?owner=Practitioner/{id} for the state, and 146 is Bundle.total on a _count=1 search, so the header count fetches no rows at all. But Results partially received, Patient plan available and Action tracking active are states in which no physician act is outstanding, and by the inbox's own rule those carry no open physician Task. They are either Tasks owned by somebody else or they arrive from somewhere else entirely, and this screen does not say which.
Two further gaps in the same primitive. A label is free text with no enum and no validation, so a typo does not fail, it quietly mints a tenth state and PN_LIFECYCLE_RANK drops that row to 99. And on the live aleronmd-dev instance Task is granted at system scope and not at user scope, so a physician-scoped token may not be able to read this list at all. That one is unresolved and it decides whether the panel is read as the physician or as the service.

fixed The pagination line asserted a property of rows nobody fetched. 137 more patients on this panel, all in states with no physician act outstanding was a claim about 146 minus 9 unread rows, and it was false on the evidence already on the two screens: the inbox says seven patients need an act, and four of the nine rows here need none. The arithmetic survives, the claim does not. It reads 137more patients on this panel and stops.

fixed The patient code embedded an age. AL-47M · 47M is a Canvas Patient.identifier carrying the age at enrolment, printed beside a live derived age, and identifiers are not rewritten. Within a year the row would read AL-47M · 48M and the identifier would be contradicting the value next to it. The derived age comes off the list row and stays in the chart, where it is read from Patient.birthDate and cannot drift.

fixed A repository path was on the product surface. docs/product/ROLE_AND_RELEASE_MATRIX_V1.md section 4 sat in the disclosure's Source row, which is a source-control path in front of a clinician and the same failure the BRIEF's API rule catches, wearing different vocabulary. The disclosure says Role and Release Matrix, section 4; the path is here.

fixed There was no way to log out, and no way to tell who was logged in. .prail__patient names the patient, so across 21 screens nothing said whose session this was and nothing ended it. v0 has both in its header, Dr. A. Okafor beside a Log out button, and the proposals dropped them when the header became a rail. A clinical surface that cannot say who is signed in cannot be handed to the next physician at the same workstation, which is the ordinary case in a clinic. The rail foot now carries the actor and the way out, under a rule, at the bottom where the least frequent act belongs. Proposed in section B as a domain.chart-rail addition, using the foot's existing exemption for a non-section action rather than claiming a new one.

fixed As bare underlined text the control was 15px tall, for the one act that ends the session. A text link is the sanctioned shape where a filled control will not fit, per register O5's fallback, but the hit area still has to be real: the label keeps its size and the target grew to 32px, with the same pointer: coarse guard the row-density variant uses restoring the full 44px floor on touch. Measured 14.35:1 flight-deck and 5.34:1 day.

new The inbox's sort pass, applied here. Lifecycle rank, held longest, held shortest, patient name, and a custom drag order with a keyboard path through the handle. A patient with no run sorts last on held rather than being given an invented age.

fixed The same invalid nesting the inbox had: <a class="pn-row"> wrapped the act button, and left nowhere legal for a drag handle. Nine rows are now divs with the patient name carrying a link that stretches over the row. Verified: the row centre hit-tests to the link, the button and the handle to themselves.

fixed Act buttons were auto-sized and right-aligned, so six labels gave six widths. One fixed track, button stretched to it: all six are 128px on a shared left edge. On the cell, not on .amd-button.

fixed Lifecycle sort put the blocked patient last. The state cell carries a hazard tile beside the words, so textContent read Signature blocked blocked, matched no rank and fell to the default. Only the cell's own text nodes are the state now. It surfaced because the sort had to parse a cell that had until then only ever been read by eye, which is the usual way a rendering detail turns out to be a data problem.

new Row density works. Lifecycle only drops the domain read and takes a row from 112px to 64px; With risk by domain restores the line, though what it restores now is a request per row rather than nine finished reads. The risk read is a second question the physician sometimes asks of the same list, which is the argument the control was already making in prose and can now demonstrate. aria-checked on the segmented control is the source of truth and the list follows it.

carried The cohort list itself, from v0/patients.html. v0's search field, patient count and row-to-chart navigation all survive; v0's grid becomes the same row anatomy the inbox uses, so the two list surfaces read as one family.

carried The six-domain risk strip, from v0/patients.html, as a density toggle. v0 encoded the tier in font weight across six three-letter tiles and put the legend 200 px below the thing it explained. new Released and tracking patients are on the list. v0's cohort had no way to show a patient whose plan is already out, which made the list read as a work queue that was missing most of its work.
