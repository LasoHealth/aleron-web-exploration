What a signature does, and what it does not
Two clocks
Signing orders and locking the note are separate acts. Sign and send transmits the orders; an order can transmit from a note that is not yet locked. Locking freezes the note and generates the archival PDF and the Canvas DocumentReference.
Asynchronous
A non-visit encounter collapses the two clocks: the note is drafted at the decision moment, so nothing is left to catch up on.
Amendment
A signed note amends by unlocking, taking the change, then locking and signing again. Canvas mints a new chart document and marks the previous one superseded; the earlier version stays readable and byte-identical. Measured 15 Sep 2026, so the chain is Canvas's work rather than something Aleron has to build.
Change of direction
A changed decision is a new entry, never an edit. The 6/14 portal encounter cancels an order placed on 6/8, and the 6/8 note is unchanged.
Release
Neither signing nor locking makes a plan patient-visible. Release is a third, separate act and it happens in Care Plan.
One signature
One authenticated signature covers every order enumerated in it. CLIA requires a valid request from an authorized person, not a per-test signature; state law or the performing lab may require more.

What changed, and where it came from

fixed There was no way to log out, and no way to tell who was logged in. .prail__patient names the patient, so across 21 screens nothing said whose session this was and nothing ended it. v0 has both in its header, Dr. A. Okafor beside a Log out button, and the proposals dropped them when the header became a rail. A clinical surface that cannot say who is signed in cannot be handed to the next physician at the same workstation, which is the ordinary case in a clinic. The rail foot now carries the actor and the way out, under a rule, at the bottom where the least frequent act belongs. Proposed in section B as a domain.chart-rail addition, using the foot's existing exemption for a non-section action rather than claiming a new one.

fixed As bare underlined text the control was 15px tall, for the one act that ends the session. A text link is the sanctioned shape where a filled control will not fit, per register O5's fallback, but the hit area still has to be real: the label keeps its size and the target grew to 32px, with the same pointer: coarse guard the row-density variant uses restoring the full 44px floor on touch. Measured 14.35:1 flight-deck and 5.34:1 day.

fixed The record rows name the resource and stop there. The API cannot create one and the API has no update for one came off: both are true, neither is the physician's to act on, and both are already in the annotation list and in BRIEF.md.

fixed The order record named a resource that does not exist. Lab Order Authorization, mirrored to Canvas is now ServiceRequest, placed by command and read back, because the Canvas FHIR API has no create for it.

new This screen's amendment doctrine turns out to be the only thing the API permits. Locked notes amend by appending, never by editing was argued from HIPAA custody; independently, DocumentReference supports create, read and search and no update, so appending is not merely the right policy, it is the only implementable one. The note record row now says so. This is the one place in the set where the doctrine and the API already agreed.

new The journal itself, from the reference surface: five entries on a time spine, the Order | Status · live from the ledger table, cross-entry jump buttons, and the signature doctrine that closes every document. v0 has no journal; it has one progress note inside the Care Plan composer.

carried Append addendum and Export PDF on locked entries, with the legal-record block above them, from v0/care-plan-note.html and its source resources/views/physician/patients/care-plan.blade.php. v1 states the doctrine that a locked note amends by appending and then gives the physician no way to append. The controls, the record dl, and the HIPAA amendment sentence are all v0's.

carried Open in EMR tab on the Canvas-sourced entry, from v0/emr.html and its source resources/views/physician/patients/emr.blade.php, along with its single sign-on caveat verbatim. v1 shows the imported document and does not say where it lives; the link is the only thing v0's EMR tab was ever for, and here it attaches to the one entry it belongs to instead of occupying a whole tab.

It renders as .pbound--quiet rather than the filled hazard boundary, because the signed text on this surface is authoritative whether or not the mirror has caught up. A degraded mirror is an advisory about another system, not a hazard in this one.

new Entry state rides on the spine node's shape, not on a tint: a filled dot is signed, an open dot is a draft, a square is imported. An external mark is a different shape.

fixed The screen said signed entries never change. The title does. Three places asserted a blanket immutability. What the instance shows is narrower and stranger: the note body has no field on the Note API that edits it, so the signed text is safe by omission rather than by rule, while PATCH of a title returned 200 on all 17 test notes including the two at SGN and the 13 at LKD (docs/canvas/INSTANCE-FINDINGS.md in Meridian-Web, X6). So the copy now claims only what holds, that nothing edits the text and a changed decision is a new entry. Whether the named author is equally mutable could not be tested: providerKey is on the same allow-list, but the instance holds one practitioner, so there is no second identity to move a note to.
