Ordering readiness

Your credentials · this patient

Every order Aleron places carries your name, so this page is the list of things that have to be true before your name can reach a lab, a pharmacy or this patient's chart. It is read here, beside the orders, because a refusal you find out about after composing an order is a refusal found too late.

You can order labs, genetic panels, imaging and referrals for Ethan Park. You cannot transmit a prescription. Your prescriber identity is not registered with the prescribing network, so a prescription you compose here can be reviewed and signed and then has to leave the practice some other way. Controlled substances need a second enrolment on that same path. Nothing else below is refusing.

Why a per-physician and practice-wide page sits inside one patient's chart

Two thirds of this page is not patient-specific: the credentials belong to the signed-in physician and the menu belongs to the practice. The question is. A physician about to order for Ethan Park needs to know whether an order for Ethan Park will carry their name and reach a lab that will run it, and answering that from a global admin page means leaving the chart to find out why an order was refused. Two rows are genuinely patient-resolved: the licensure row against the patient's address, and the collection row against the patient's state.

The previous version of this screen presented two configured standing-order records as the authorization for an order, with the caption "this is the NPI Junction receives, whoever places the order". Neither half held. No physician object was sent, so the lab's own network was validating the order; and under the current requirement every order names the signed-in physician, which a config-level NPI cannot do for them.

Chart access
Authorization Code with PKCE per physician, refresh token rotated. Attribution follows the token; a service key records the bot instead. No just-in-time provisioning, so an unprovisioned physician is a stop, not a fallback.
Practitioner record
Canvas Staff.id. Plain data at sign time with no validation, so Aleron has to enforce that the named physician and the committing physician agree.
Licensure
Junction types licensed_states as a bare string list and documents no cross-check against the patient address. Aleron owns the gate.
Menu
Nightly reconcile of GET /v3/lab_tests and GET /v3/lab_test/lab_account, cached. Splits not active at the lab from not offered on this account, which the old count of non-empty env vars could not.
Coverage
Testkit and walk-in: 49 states, excluding New York. At-home phlebotomy: 35 states.
Account setting
delegated_flow, currently order_delegated. result_delegated and not_delegated make a supplied physician a no-op. Enforcement is in a grace period, so an order with no physician supplied also falls back silently; read the physician back off every placed order.
Physician can edit
Their own registration and enrolment. The menu and the account setting are Admin, per section 2 of the role matrix.

What changed, and where it came from

new The screen's premise was invalidated, and it is now a readiness surface rather than an authorization record. Its central claim was that a configured standing order, with a reference and an ordering-physician NPI, is what authorizes an order, captioned "this is the NPI Junction receives, whoever places the order". The requirement is now that every order names the physician signed into Aleron, so a config-level NPI authorizes nothing and cannot be made to. Same facts, new question: what has to be true before my name can reach a lab, a pharmacy or this chart? Renamed Ordering readiness. Standing orders named the artefact, and the artefact is no longer the subject: it survives as the practice's record of what the menu may contain, which is one quiet block at the foot rather than the whole page. The filename is unchanged so no other screen's link breaks, and the label on the inbox rail foot and in the flow map still reads Standing orders, which is a rename to carry through those two files.

new Per-physician credentials, the block that did not exist. Six rows, each a precondition for some order type, in the order a refusal reaches you: chart access, practitioner record, NPI, licensed states, prescription transmission, controlled substances. The physician who is missing one needs the consequence, not the field, so every row states what it stops. Chart access is a one-time per-physician act with no fallback and no way to do it for them, which makes it the first row and a genuine first-class state rather than an error. This is the block that carries the requirement: it is the only place on the surface where the identity on an order is a person's rather than a setting's.

new Prescription transmission is a hazard tile; controlled substances is an advisory. Not holding a prescriber identity with the prescribing network is a hard stop on transmission and the one thing on this page that blocks an order type, so it takes the ember tile per P3 and the screen's only action, a real control in the row that stops it. Controlled-substance enrolment narrows the same signing path rather than opening a second one, so it is words in advisory colour and never a tile, and the true blocker outranks it by construction.

new The licensure gate nobody was performing. The lab types the physician's licensed states as a bare list and documents no check against the patient's address, so if Aleron names a physician, Aleron owns the gate. The row resolves against this patient's state and says out loud that it is the only thing checking.

new State coverage, which no screen carried. Kits and walk-in collection reach 49 states and not New York; an at-home draw reaches 35. An order can therefore fail on geography under credentials that are entirely in order, which is the failure this set had no surface for at all. Resolved against the patient's state so it reads as an answer rather than a fact sheet.

new Who reviews the results, from the practice account's delegation setting. The setting decides whether critical follow-up stays with the lab or comes to Aleron, and two of its four values hand ordering back to the lab's own physician network while quietly ignoring the physician on the order. That is a silent breach of the requirement, so it is on the screen, with the read-back check that is the only thing that would detect it. The abnormal-result row states the harder fact: nothing announces an abnormal that is not critical, and a partial result announces nothing at all, so they are looked for rather than awaited.

fixed A PHP class name was printed to the physician. The rollup rendered StandingOrder::for('genetics') inside a value span, which is exactly the pattern check.js's api-on-product-surface rule exists to catch, and a physician acts on none of it. The rollup now counts what it should have counted all along: order types this physician cannot complete right now.

fixed Two fabricated facts are gone. Signed 14 Jan 2026, Signed 3 Feb 2026 and countersigned by the medical director exist in no system: no signature date and no countersignatory field is held anywhere, and they sat under the caption style this set uses for sourced provenance, on the one screen where an invented date is a real liability. Removed rather than configured, because under the new model the document's signature is not what authorizes the order. Separately, the cards named Dr. A. Okafor as the NPI's owner by inferring it from whoever was signed in, so the second physician to use the portal would have been shown as the authorizing physician on a record they had never seen. The NPI is now the signed-in physician's own, in the credential block, which is the only reading that is true by construction.

fixed The fail-soft caption was inverted. "Canvas order-authorization writes fail soft, with no clinician attribution on the record. The order still transmits; only the Canvas attribution is lost." The real behaviour was the opposite and worse: with no practitioner record nothing is written at all, so the chart carries no evidence the order was ever placed. Under the new model that case cannot arise silently, because an unmatched practitioner record stops the order rather than degrading it, and the row says so.

fixed The rail marked Care Plan as the current page. This surface is reached from the rail foot, so the current-page marker moved to the foot link and the six chart sections no longer claim a selection that is not theirs.

gap The menu is now reconciled against the labs, and that reconciliation does not exist yet. 16 entries, 14 orderable here was a count of non-empty configuration values presented as a claim about the world, and it could read Orderable for a test the lab had withdrawn. The menu now carries four states, and the two new ones separate two problems with two different owners: Not active at the lab is the lab's own menu changing under us, Not offered on this account is a purchasing question, and Approved, not yet set up is the provisioning task the old single string conflated with both. Needs a nightly reconciliation job with a cache, never a call on page render. The per-row lab name comes from the same read, which also retires sixteen hand-authored (Quest) suffixes that would have kept saying Quest against a Labcorp account.

gap The genetic counseling acknowledgment has no home outside Aleron. It is a physician attestation of fact and it belongs on the order, not on this menu, so the advisory says where it is made and stops. Modelling it as a patient consent would file the physician's attestation in the patient's consent ledger, where an auditor reads it as the patient consenting, and the lab's own consent list is a closed set with no member that means this.

carried The test menu itself and the two standing-order references, from v0/standing-orders.html. v1 has no ordering surface at all, so it has no concept of what authorizes an order. The menu is the reason the screen exists; what changed is what it is reconciled against.

carried Fail-closed as the default, from v0's rollup and both controllers' gates. An order under something that does not fully resolve refuses rather than transmitting on a partial record, and that is still the behaviour every row on this page describes.

carried The signed-in actor and the way out, in the rail foot. .prail__patient names the patient, so across 21 screens nothing said whose session this was and nothing ended it, while v0 had both in its header. On this screen it earns its place twice over: every credential row above is a property of that named physician, so the name in the foot is what makes the block legible.

dropped The two ordering-physician NPI rows, and the kill-switch rows. A config-level NPI authorizes nothing under the new requirement, so a row asserting it as the ordering physician is not fixable by rewording. The per-type kill switches went with them: ordering is off for genetics in this environment is a deployment state, not a fact about this physician or this patient, and it belongs with the release controls rather than in front of a clinician who cannot act on it.

dropped The catalog keys blood and genetics, and the two-card split. Internal enum values on the product surface, and a split that made the physician read two nearly identical records to answer one question. One menu, two group headers, which also lets the counts be a single number.

dropped The Model under review advisory. It said the authorization model for genetics should move from standing-order authorization to an individual physician's order carrying a counseling acknowledgment. That review has landed and this screen is its outcome, so the advisory would now be describing the page it sits on. Its comparison of two enforcement paths went with it: it rested on a controller built for the superseded model.

dropped v0 elevates both cards to Tier 1. Two elevated cards spend the emphasis budget twice; the credential block keeps the elevation, because it is the only block on the page whose contents the physician can change, and the other two are flat.
